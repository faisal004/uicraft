Before you begin, remember one idea: **canvas is a bitmap you draw into with JavaScript.** A circle on canvas is colored pixels, not a circle element you can inspect in the DOM. Work through the lessons in order. Change one number in each snippet before moving on.

<h2 id="lesson-1">1. The drawing surface</h2>

Start with ordinary HTML. The `<canvas>` element gives you an empty drawing surface. Its `width` and `height` attributes set the number of drawing units inside it. The text between the tags is a fallback for browsers that cannot use canvas.

```html
<canvas id="board" width="600" height="300">
  Your browser does not support canvas.
</canvas>
```

JavaScript asks that element for a **2D context**. Call it `ctx`: it is the pen you will use for almost everything in this course. If the context is unavailable, stop before drawing.

```js
const canvas = document.querySelector("#board")
const ctx = canvas.getContext("2d")
if (!ctx) throw new Error("2D canvas is unavailable")
```

At this point the canvas is still blank. Unlike HTML, drawing does not happen because you added child elements. You must issue drawing commands.

**Check yourself:** What are `canvas` and `ctx`? The canvas is the surface; `ctx` is the API used to draw on it.

<h2 id="lesson-2">2. Canvas size: pixels inside versus size on screen</h2>

This is the first common trap. `<canvas width="300" height="150">` creates a **300 × 150 drawing buffer**. CSS `width` and `height` change how large that buffer appears on screen. If CSS makes it 300 × 270 without changing the buffer, the browser stretches the old image. A circle becomes an oval.

Move the height slider. First leave the checkbox off, then turn it on. Look at the blue circle.

<CanvasSizeDemo />

For a fixed 300 × 150 canvas, give the CSS box the same proportions. For a responsive canvas, measure the box and update the drawing buffer too. On a high-density screen, multiply the buffer by `devicePixelRatio` and scale the context so your drawing commands still use CSS pixels.

```js
const box = canvas.getBoundingClientRect()
const dpr = window.devicePixelRatio || 1
canvas.width = Math.round(box.width * dpr)
canvas.height = Math.round(box.height * dpr)
ctx.setTransform(dpr, 0, 0, dpr, 0, 0)
// Now draw using box.width and box.height as your logical size.
```

Setting `canvas.width` or `canvas.height` **clears the drawing** and resets context settings. Resize first, then set styles and draw again. CSS alone can resize the box, but it cannot add detail to an undersized drawing buffer.

**Try this:** make the displayed height 270. With the checkbox off, predict the circle's shape. Then turn it on and compare.

<h2 id="lesson-3">3. Coordinates: where is (0, 0)?</h2>

Canvas coordinates start at the **top left**. `x` grows to the right; `y` grows downward. On this 600 × 300 canvas, `(300, 150)` is the center. The grid below marks every 50 units.

```text
(0, 0) ───────────────→ x
   │
   │       (300, 150)
   ↓
   y
```

**Check yourself:** Where would you place a point near the bottom right? Something like `(550, 250)`.

<h2 id="lesson-4">4. Rectangles and color</h2>

`fillStyle` chooses the color for future fills. `fillRect(x, y, width, height)` paints a rectangle. Its first two numbers locate the top-left corner; the next two describe its size.

```js
ctx.fillStyle = "#2563eb"
ctx.fillRect(50, 65, 180, 100)
```

<CanvasBasicsStep step="1" />

**Try this:** change `50` to `150`. Predict which way the rectangle moves before you look at the grid. A negative width is not how you position it; move its `x` instead.

Drawing order matters. A later shape can cover an earlier one, like adding paint on top of paint. `strokeRect` draws an outline, and `clearRect` erases a region back to transparency.

<h2 id="lesson-5">5. Paths and circles</h2>

Rectangles have a shortcut, but most shapes use a **path**: begin one, describe its geometry, then fill or stroke it. `arc` takes a center, radius, start angle, and end angle. A full circle ends at `Math.PI * 2` radians.

```js
ctx.beginPath()
ctx.arc(430, 115, 50, 0, Math.PI * 2)
ctx.fillStyle = "#f59e0b"
ctx.fill()
```

<CanvasBasicsStep step="2" />

`beginPath()` matters. Without it, a later `fill()` or `stroke()` can reuse parts of a previous path. To draw a line, use `moveTo(x, y)`, then `lineTo(x, y)`, then `stroke()`.

**Try this:** the circle's center is `(430, 115)` and its radius is `50`. What are its left and right edges? They are `x = 380` and `x = 480`.

<h2 id="lesson-6">6. Text is also drawing</h2>

Choose a font and call `fillText`. By default, its `x` value marks the text's left edge and its `y` value marks the **baseline** the letters sit on. You can change alignment with `textAlign` and `textBaseline`.

```js
ctx.fillStyle = "#0f172a"
ctx.font = "bold 44px Arial"
ctx.fillText("Hello, canvas!", 150, 242)
```

<CanvasBasicsStep step="3" />

Canvas text becomes pixels. It is not selectable or readable like an ordinary `<h1>`. Use real HTML for meaningful page content. Draw text on canvas when the pixels themselves are part of the effect.

**Try this:** change `242` to `200`. Predict whether the words move up or down.

<h2 id="lesson-7">7. State, clearing, and drawing again</h2>

Canvas keeps its drawing until you erase it or change its size. Styles such as `fillStyle`, line width, alignment, and transforms also stay in the context until changed. `save()` and `restore()` let you temporarily change settings without leaking them into the next drawing.

```js
ctx.save()
ctx.fillStyle = "tomato"
ctx.fillRect(20, 20, 80, 80)
ctx.restore()
// The fillStyle is now whatever it was before save().
```

To replace a frame, clear it and draw the new one. `clearRect` makes pixels transparent. If you want a solid background, paint a full-size rectangle after clearing.

```js
ctx.clearRect(0, 0, canvas.width, canvas.height)
ctx.fillStyle = "white"
ctx.fillRect(0, 0, canvas.width, canvas.height)
```

That clearing example assumes the context has its default scale. If you used `setTransform(dpr, ...)` in lesson 2, clear using the **logical CSS width and height** instead, because your drawing coordinates are scaled.

**Check yourself:** What happens if you draw a moving circle without clearing? Every old circle remains, making a trail.

<h2 id="lesson-8">8. Animation is repeated drawing</h2>

There is no “move this circle” command because the circle is already pixels. Instead, clear the old image, calculate a new position, draw again, and ask the browser for the next frame. `requestAnimationFrame` gives you a timestamp so motion depends on time rather than computer speed.

```js
let frame
const started = performance.now()

function draw(time) {
  ctx.clearRect(0, 0, 600, 300)
  const x = 80 + (Math.sin((time - started) / 700) + 1) * 200
  ctx.beginPath()
  ctx.arc(x, 150, 34, 0, Math.PI * 2)
  ctx.fillStyle = "#2563eb"
  ctx.fill()
  frame = requestAnimationFrame(draw)
}

frame = requestAnimationFrame(draw)
// When leaving this page or stopping: cancelAnimationFrame(frame)
```

<CanvasBasicsStep step="4" />

The `Math.sin(...)` part makes `x` travel back and forth. Ignore the formula at first; focus on the loop: **clear → calculate → draw → repeat**. The live example redraws the grid each frame too.

**Try this:** change `700` to `1400`. Will the circle move faster or slower? Slower.

<h2 id="lesson-9">9. A pointer uses a different coordinate system</h2>

Pointer events report coordinates in the browser window. Canvas drawing uses coordinates inside the drawing buffer. First subtract the canvas's position on screen; then account for any CSS scaling. Move your pointer over this demo and watch the numbers.

<CanvasPointerDemo />

```js
canvas.addEventListener("pointermove", (event) => {
  const box = canvas.getBoundingClientRect()
  const x = (event.clientX - box.left) * canvas.width / box.width
  const y = (event.clientY - box.top) * canvas.height / box.height
  // Draw at (x, y), then redraw the scene on the next move.
})
```

If you use a high-density buffer and called `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)`, draw with **CSS-pixel coordinates** instead: use `event.clientX - box.left` and `event.clientY - box.top`. Keep your input coordinates and drawing coordinates in the same system.

**Try this:** shrink the browser width. The dot should still follow the pointer even though the canvas looks smaller.

<h2 id="lesson-10">10. Read pixels and make the bridge to particles</h2>

`getImageData` lets you inspect the colored pixels in a canvas. Each pixel uses four numbers: **red, green, blue, alpha**. Alpha is 0 for transparent and 255 for fully opaque. The position of pixel `(x, y)` in the flat array is `(y * width + x) * 4`.

Here is a useful trick: draw a word on a second, offscreen canvas; read its alpha values; draw a dot where the letters have visible pixels.

```js
const mask = document.createElement("canvas")
mask.width = 600
mask.height = 300
const pen = mask.getContext("2d")
pen.font = "bold 110px Arial"
pen.textAlign = "center"
pen.textBaseline = "middle"
pen.fillText("HELLO", 300, 150)

const pixels = pen.getImageData(0, 0, 600, 300).data
ctx.fillStyle = "#2563eb"
for (let y = 0; y < 300; y += 5) {
  for (let x = 0; x < 600; x += 5) {
    const alpha = pixels[(y * 600 + x) * 4 + 3]
    if (alpha > 128) ctx.fillRect(x, y, 3, 3)
  }
}
```

<CanvasBasicsStep step="5" />

The `5` controls sampling distance. Smaller steps create more dots and more work. Larger steps create a rougher image. Those `(x, y)` locations can become particles: store them, change their positions each frame, then redraw. That is the core idea behind Text to Particles.

**Try this:** imagine replacing `fillRect(x, y, 3, 3)` with `fillRect(x + 20, y, 3, 3)`. Which way would the dotted word move?

## Your first small project

Make a circle follow your pointer. Use lesson 1 to create the canvas, lesson 5 to draw a circle, lesson 7 to clear the old drawing, and lesson 9 to convert pointer coordinates. When that works, draw a word on an offscreen canvas and sample its pixels as in lesson 10. You now have the pieces needed to understand [Text to Particles](/craft/text-to-particles) and [Thanos Snap](/craft/thanos-snap).

If you get stuck, identify the kind of problem first: **size**, **coordinates**, **drawing state**, **animation loop**, or **pixel data**. Most canvas bugs belong to one of those five buckets.
