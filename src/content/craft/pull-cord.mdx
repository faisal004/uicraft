Pull the handle down until it turns orange, then let go. The whole site switches theme, and the cord snaps back, overshoots, and swings until it settles. Tap the handle or focus it and press Enter for a quick tug.

## How it works

The cord isn't an animation with keyframes. It's a tiny physics simulation that runs about 120 times a second. Nothing tells the cord to swing. It swings because gravity pulls it down, the ceiling holds the top, and the pieces of the cord pull on each other.

The method is called **Verlet integration**. It's the same trick used for cloth, hair, and ragdolls in games because it's short to write and very hard to make explode. You only need three ideas:

1. **Points.** The cord is a chain of 12 points.
2. **Motion.** Each point keeps moving the way it was moving, and gravity adds a bit of downward speed.
3. **Constraints.** Neighbouring points are pushed back to a fixed distance apart, so the chain behaves like one piece of string.

Each step below adds one of those ideas, so you can watch what each one does on its own.

### 01 — Draw the cord

<PullCordStep step="1" />

Start with what you see: an `<svg>` with a small mount at the top and one `<path>` for the cord. A path's `d` attribute is a list of drawing commands. `M x y` moves the pen, `Q cx cy x y` draws a curve that bends towards the control point `cx cy`, and `L x y` draws a straight line.

The scene is a fixed `200 × 300` box, and the SVG is drawn at exactly that size, so one SVG unit is one CSS pixel. The top of the cord, the **anchor**, sits at the middle of the top edge.

The cord is stored as points. Each point has a current position (`x`, `y`) and a previous position (`px`, `py`). For now both are the same, which means "not moving". The orange dots show where the points are; the dark one is the anchor.

```tsx title="pull-cord.tsx"
const WIDTH = 200;
const HEIGHT = 300;
const ANCHOR = { x: WIDTH / 2, y: 0 };

const POINTS = 12;
const LENGTH = 130; // rest length of the whole cord
const SEGMENT = LENGTH / (POINTS - 1); // rest length between two neighbouring points

function createRope(): Point[] {
  return Array.from({ length: POINTS }, (_, i) => {
    const y = ANCHOR.y + i * SEGMENT;
    return { x: ANCHOR.x, y, px: ANCHOR.x, py: y };
  });
}
```

To turn points into a smooth line, `ropePath` uses each point as a curve's control point and the midpoint between two points as where the curve passes. That rounds off every corner, so 12 points look like a soft string instead of a zigzag.

```tsx title="pull-cord.tsx"
function ropePath(points: Point[]) {
  const n = (value: number) => value.toFixed(1);
  let d = `M ${n(points[0].x)} ${n(points[0].y)}`;
  for (let i = 1; i < points.length - 1; i++) {
    const a = points[i];
    const b = points[i + 1];
    d += ` Q ${n(a.x)} ${n(a.y)} ${n((a.x + b.x) / 2)} ${n((a.y + b.y) / 2)}`;
  }
  const end = points[points.length - 1];
  return `${d} L ${n(end.x)} ${n(end.y)}`;
}
```

### 02 — Give the points motion

<PullCordStep step="2" />

Here's the core of Verlet integration: **velocity isn't stored anywhere**. A point's velocity is simply where it is now minus where it was one step ago. To move a point forward one step:

1. Work out its velocity: `x - px`.
2. Shrink it a little with `DAMPING`. Keeping 98.5% each step is like air resistance. Without it the cord would swing forever.
3. Remember the current position as the previous one.
4. Add the velocity to the position, plus `GRAVITY` on the y axis. Adding a little extra downward movement every step is what makes things accelerate as they fall.

The loop starts at `1` because point `0` is the anchor and never moves.

```tsx title="pull-cord.tsx"
const GRAVITY = 0.12; // px per step²
const DAMPING = 0.985; // share of velocity kept each step

function integrate(points: Point[]) {
  for (let i = 1; i < points.length; i++) {
    const p = points[i];
    const vx = (p.x - p.px) * DAMPING;
    const vy = (p.y - p.py) * DAMPING;
    p.px = p.x;
    p.py = p.y;
    p.x += vx;
    p.y += vy + GRAVITY;
  }
}
```

A nice side effect: to push a point you don't set a velocity, you just move its *previous* position. The Replay button does that, nudging `px` to the left on the lower points, so they drift right as they fall.

In this step nothing holds the points together, so they fall off the bottom. That's correct: so far these are 11 separate pebbles, not a string.

**Running it.** The browser calls `requestAnimationFrame` once per screen refresh, which is 60 times a second on most screens and 120 or more on others. If the simulation took one step per frame, the cord would fall twice as fast on a 120 Hz screen. Instead the loop adds the elapsed time to a balance it `owes`, then takes as many fixed 120 Hz steps as that balance pays for. If the tab was in the background for a while, the balance is capped so the cord doesn't try to catch up on seconds of physics at once.

```tsx title="pull-cord.tsx"
const STEP_MS = 1000 / 120; // the simulation always advances in 120 Hz steps

function tick(now: number) {
  // Run as many fixed steps as the elapsed time owes; cap the backlog after a stalled tab.
  owed = Math.min(owed + now - last, STEP_MS * 8);
  last = now;
  // ...
  while (owed >= STEP_MS) {
    integrate(points);
    if (stage >= 3) constrain(points, grab.current);
    owed -= STEP_MS;
  }
  // ...
  draw();
```

`draw` writes the new path straight onto the `<path>` element with `setAttribute`. It doesn't go through React state, because re-rendering a component 120 times a second for one attribute would be wasted work.

### 03 — Hold them together

<PullCordStep step="3" />

A string doesn't fall apart because each bit of it is tied to the next. We copy that with a **distance constraint**: for each pair of neighbours, measure how far apart they are, compare it to `SEGMENT`, and move both points to fix the difference.

- If they're too far apart, `pull` is positive and the points move towards each other.
- If they're too close, `pull` is negative and they move apart.
- `STIFFNESS` of `0.5` fixes half the error each pass. Fixing it all at once makes the cord jittery, because fixing one pair breaks its neighbours.
- `share` decides who moves. Normally both points move half the way. The anchor never moves, so the point under it takes the whole fix.

One pass over the chain isn't enough, because each fix nudges the next pair out of place. Running `PASSES = 6` passes per step lets the corrections spread along the cord.

```tsx title="pull-cord.tsx"
const STIFFNESS = 0.5; // share of a length error fixed per pass
const PASSES = 6; // constraint passes per step

function pin(p: Point, to: Vec) {
  p.x = p.px = to.x;
  p.y = p.py = to.y;
}

function constrain(points: Point[], grab: Vec | null) {
  const last = points.length - 1;
  for (let pass = 0; pass < PASSES; pass++) {
    pin(points[0], ANCHOR);
    if (grab) pin(points[last], grab);
    for (let i = 1; i <= last; i++) {
      const a = points[i - 1];
      const b = points[i];
      const dx = b.x - a.x;
      const dy = b.y - a.y;
      const distance = Math.hypot(dx, dy) || 1;
      const pull = ((distance - SEGMENT) / distance) * STIFFNESS;
      // How much of the fix `a` takes. A pinned point takes none of it.
      const share = i === 1 ? 0 : grab && i === last ? 1 : 0.5;
      a.x += dx * pull * share;
      a.y += dy * pull * share;
      b.x -= dx * pull * (1 - share);
      b.y -= dy * pull * (1 - share);
    }
  }
}
```

Notice there's no code here about swinging. Gravity pulls each point down, the constraint drags it back towards the anchor, the leftover velocity carries it past the middle, and damping slowly eats the energy. Swinging is what falls out.

### 04 — Grab the handle

<PullCordStep step="4" />

Now the bottom point gets a handle you can drag. The handle is a rounded `<rect>` inside a `<g>`, moved to the last point each frame and rotated to follow the last segment, so it hangs at the angle of the cord.

Pointer events turn your finger or mouse into a second pin:

- `pointerdown` calls `setPointerCapture`, so the handle keeps getting `pointermove` events even when the pointer slides off it.
- The pointer position is converted from screen pixels into scene units with `getBoundingClientRect`.
- While it's held, `grab.current` is set, and `constrain` pins the last point there, just like the anchor.
- `touch-none` (CSS `touch-action: none`) stops the page from scrolling while you drag on a phone.

```tsx title="pull-cord.tsx"
function onPointerDown(event: PointerEvent<SVGGElement>) {
  if (!canGrab) return;
  event.currentTarget.setPointerCapture(event.pointerId);
  pressStart.current = toScene(event);
  grab.current = clampGrab(pressStart.current);
  wake.current();
}
```

With both ends pinned, the constraints can't get every segment back to its rest length, so the cord **stretches**. When you let go, the last point is free again. Each segment is longer than `SEGMENT`, so the constraints pull it back hard, it overshoots above the rest position, and gravity swings it back down. That springy recoil comes from the same constraint code as the swing.

`clampGrab` stops the stretch at `MAX_STRETCH` past the cord's length, so you can't drag the cord across the page.

```tsx title="pull-cord.tsx"
const MAX_STRETCH = 70; // how far past its rest length the cord can be pulled

function clampGrab(to: Vec): Vec {
  const dx = to.x - ANCHOR.x;
  const dy = to.y - ANCHOR.y;
  const distance = Math.hypot(dx, dy) || 1;
  const max = LENGTH + MAX_STRETCH;
  if (distance <= max) return to;
  return { x: ANCHOR.x + (dx / distance) * max, y: ANCHOR.y + (dy / distance) * max };
}
```

### 05 — Pull to toggle

<PullCordStep step="5" />

A real pull switch clicks partway down, and the light changes when you let go. The stretch is the distance from the anchor to the handle minus the cord's rest length. Past `TRIGGER` the switch **arms**: it plays a click and the handle turns orange. Releasing while armed flips the theme. Releasing before that just lets the cord bounce back.

```tsx title="pull-cord.tsx"
const TRIGGER = 38; // pull past this and let go to toggle

function stretchOf(points: Point[]) {
  const end = points[points.length - 1];
  return Math.hypot(end.x - ANCHOR.x, end.y - ANCHOR.y) - LENGTH;
}

function onPointerMove(event: PointerEvent<SVGGElement>) {
  if (!grab.current) return;
  grab.current = clampGrab(toScene(event));
  if (canToggle) setArmedOnce(stretchOf(rope.current) > TRIGGER);
}

function onPointerUp(event: PointerEvent<SVGGElement>) {
  if (!grab.current) return;
  const start = pressStart.current!;
  const end = toScene(event);
  grab.current = null;
  pressStart.current = null;
  if (canToggle) {
    if (armedRef.current) toggle();
    else if (Math.hypot(end.x - start.x, end.y - start.y) < 4) tug();
  }
  setArmedOnce(false);
}
```

Flipping the theme is the same as the site's header button: add or remove the `dark` class on `<html>`, set `color-scheme` so form controls and scrollbars match, and save the choice in `localStorage`.

```tsx title="pull-cord.tsx"
function setDark(dark: boolean) {
  const root = document.documentElement;
  root.classList.toggle("dark", dark);
  root.style.colorScheme = dark ? "dark" : "light";
  try {
    localStorage.setItem("theme", dark ? "dark" : "light");
  } catch {
    // The theme still changes when storage is unavailable.
  }
}
```

A `MutationObserver` watches that class too, read through React's `useSyncExternalStore`, so if you switch the theme from the header, the cord's switch state stays in sync.

### 06 — Keyboard, screen readers, and reduced motion

Dragging is the fun way in, but it can't be the only one.

- The handle has `role="switch"`, `aria-checked`, and the label "Dark theme", so a screen reader announces it as "Dark theme, switch, off". `tabIndex={0}` puts it in the tab order, and a ring shows on `:focus-visible`.
- A tap without dragging, or Enter or Space, calls `tug`. It kicks the lower points downward by moving their previous positions up, so the cord jerks and swings, then flips the theme straight away.

```tsx title="pull-cord.tsx"
function tug() {
  if (!reducedMotion.current) {
    rope.current.forEach((p, i) => (p.py = p.y - 9 * (i / (POINTS - 1)) ** 2));
  }
  playClick();
  toggle();
  wake.current();
}
```

- With **reduced motion** turned on, there's no simulation at all. The cord is drawn as a straight line from the anchor to the handle, follows your drag, and jumps straight back when you let go. The toggle still works the same way.

```tsx title="pull-cord.tsx"
function layStraight(points: Point[], end: Vec) {
  points.forEach((p, i) => {
    const t = i / (points.length - 1);
    pin(p, { x: ANCHOR.x + (end.x - ANCHOR.x) * t, y: ANCHOR.y + (end.y - ANCHOR.y) * t });
  });
}
```

### 07 — Let it sleep

A cord that has stopped swinging doesn't need 120 steps a second. After each frame the loop checks whether any point still moved more than a hundredth of a pixel. Once the cord has been still for 30 frames, the loop stops asking for frames. Grabbing, tapping, or pressing a key calls `wake`, which starts it again. When the component unmounts, the effect cleanup cancels any pending frame.

```tsx title="pull-cord.tsx"
// Sleep once the rope has been still for half a second.
still = grab.current || isMoving(points) ? 0 : still + 1;
if (still > 30) {
  frame = 0;
  return;
}
frame = requestAnimationFrame(tick);
```

## Things to try

- Pull slowly and stop just before the handle turns orange, then let go. The cord bounces but the theme stays.
- Drag the handle far to one side and release it to get a big swing.
- Change `GRAVITY` to `0.03` for a cord that floats like it's underwater, or `DAMPING` to `0.999` for one that barely stops.
- Drop `PASSES` to `1`. The cord turns stretchy, like a rubber band.
