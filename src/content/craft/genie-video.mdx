## How it works

This effect looks like one piece of magic, but it's four ordinary ideas stacked together:

1. **Mark the start and end with empty boxes.** The page layout decides where the video begins and where it lands. The animation never moves real elements.
2. **Draw the video yourself.** A WebGL canvas paints the current video frame onto a mesh of tiny triangles that you control.
3. **Turn scroll into a number.** One value from `0` to `1` says how far along the fold is.
4. **Let every point run a little late.** If every point on the mesh moves at once, you get a plain shrink. If points near one corner move first, the sheet bends. That bend is the genie.

The steps below build it in that order. Each one has a small diagram, and the interactive ones run the same maths as the real component, so you can drag a slider and watch exactly what the shader does.

### 01 — Start with two empty boxes

Before any animation, build the page as if the video were a plain image. There's a scrollable post, a 16:9 **cover** box above the title, and a small **dock** box pinned to the bottom-right corner. Both boxes are `invisible`: they keep their size and position in the layout but draw nothing.

This is the most important design decision in the whole effect. The video never lives inside either box. The boxes are just measuring tapes: "start here", "end here". Because nothing real moves, the text never reflows, and you can change where the video starts or lands just by moving a box with CSS.

<GenieVideoFigure step="layout" />

```tsx title="01-layout.tsx"
<div ref={scrollerRef} className="absolute inset-0 overflow-y-auto">
  <div ref={coverRef} aria-hidden="true" className="invisible aspect-video w-full max-w-[460px]" />
  <article>…the post…</article>
</div>

<canvas ref={canvasRef} aria-hidden="true" className="pointer-events-none absolute inset-0" />

<button ref={dockRef} type="button" aria-label="Back to the cover video"
  className="absolute right-3 bottom-3 aspect-video w-[min(40%,200px)]" />
```

Three details matter here:

- The **canvas** lies on top of the whole scroll area. `pointer-events: none` makes it transparent to the mouse, so wheel, touch and clicks reach the post underneath.
- The cover box has `aria-hidden="true"` because it's empty; screen readers have nothing to read there.
- The **dock** is a real `<button>`, because later it becomes the way back to the top. A `<div>` would need extra work to be focusable and keyboard-friendly.

On the full blog page the same three elements exist, but the canvas and dock are `position: fixed` to the browser window instead of `absolute` inside a box.

### 02 — Draw the video on a canvas with WebGL

CSS transforms can move, scale, rotate and skew an element, but every one of them keeps straight edges straight. A genie needs the edges to curve, so we have to draw the video ourselves.

**WebGL** is the browser's API for drawing with the GPU. Everything it draws is made of triangles. You give it a list of points; it fills the triangles between them and paints an image across them. Bend the points and the image bends with them.

<GenieVideoFigure step="texture" />

The video is a normal `<video>` element created in JavaScript and never added to the page. It must be `muted`: browsers only allow autoplay for silent video. `playsInline` stops iPhones from opening it full screen.

A **texture** is an image stored on the GPU, ready to be painted onto triangles. `texImage2D` copies the video's current frame into the texture. Because video changes over time, we do that copy every frame.

```ts title="02-video-texture.ts"
const video = document.createElement("video");
video.src = src;
video.muted = true;
video.loop = true;
video.playsInline = true;
video.play().catch(() => {});

const gl = canvas.getContext("webgl", { premultipliedAlpha: true, antialias: true });

const render = () => {
  raf = requestAnimationFrame(render);
  if (video.readyState < 2) return; // no frame decoded yet
  gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, video);
  // …draw…
};
raf = requestAnimationFrame(render);
```

`requestAnimationFrame(render)` asks the browser to call `render` just before it paints the next frame, usually 60 times a second. `render` schedules itself again on its first line, which makes a loop that stays in step with the screen and pauses when the tab is hidden.

`video.readyState < 2` means the browser hasn't decoded a frame yet. Uploading then would give an empty texture, so we skip the frame and try again.

`video.play()` returns a promise that rejects if the browser blocks playback. `.catch(() => {})` keeps that from becoming an uncaught error.

### 03 — Use a grid, not four corners

If the plane only had its four corners, WebGL could make a trapezium but never a curve: the edge between two points is always a straight line. To get a curve, put many points along every edge and inside the plane, then move each one separately. Short straight segments, close together, read as a smooth curve.

Drag the slider to see how the grid is built. With 1 cell you get just two triangles and straight edges. More cells give the shape more places to bend.

<GenieVideoFigure step="grid" />

```ts title="03-grid.ts"
for (let y = 0; y <= GRID; y++)
  for (let x = 0; x <= GRID; x++) positions.push(x / GRID, y / GRID);

for (let y = 0; y < GRID; y++) {
  for (let x = 0; x < GRID; x++) {
    const i = y * (GRID + 1) + x;
    indices.push(i, i + 1, i + GRID + 1, i + 1, i + GRID + 2, i + GRID + 1);
  }
}
```

The first loop lists the points. Each point stores where it is on the video, from `(0, 0)` at the top-left to `(1, 1)` at the bottom-right. These numbers never change; they're the point's address on the picture.

The second loop joins the points into triangles. For each cell, `i` is its top-left point. `i + 1` is the point to its right, and `i + GRID + 1` is the point directly below, one full row later. Each cell becomes two triangles: top-left, top-right, bottom-left; then top-right, bottom-right, bottom-left. Storing triangles as point numbers (an **index list**) lets neighbouring triangles share points instead of repeating them.

In the shader, each point's address arrives as `a_pos`. An **attribute** is a value that is different for every point.

### 04 — Measure the boxes and the scroll

Every frame, `getBoundingClientRect()` returns each box's position and size on screen in CSS pixels. We subtract the canvas's own position so every number is measured from the canvas's top-left corner. That's why one piece of code works both inside a small box and over the whole window.

Then scroll turns into **progress**, a single number from `0` (cover) to `1` (docked). `fit` is a tiny helper: `(value − start) / (end − start)`, clamped to `0..1`. The fold finishes once you've scrolled 70% of the cover's height, which feels quick without being jumpy.

Drag the scroll slider. The real cover box (dotted) moves up with the page. The box the video leaves from (dashed) stays put.

<GenieVideoFigure step="scroll" />

```ts title="04-measure.ts"
const area = canvas.getBoundingClientRect();
const scroll = scroller ? scroller.scrollTop : window.scrollY;
const a = cover.getBoundingClientRect();
const b = dock.getBoundingClientRect();

// Where the cover sat before any scrolling, so the video leaves from there.
const coverTop = a.top - area.top + scroll;
const progress = fit(scroll, 0, a.height * 0.7);

gl.uniform2f(uni.fromXY, a.left - area.left, coverTop);
gl.uniform2f(uni.fromWH, a.width, a.height);
gl.uniform2f(uni.toXY, b.left - area.left, b.top - area.top);
gl.uniform2f(uni.toWH, b.width, b.height);
gl.uniform1f(uni.progress, progress);
```

Why freeze the start box? If the video started from the cover's live position, two things would pull it in opposite directions: scrolling would drag it up off the screen while the fold pulled it down to the dock. The trailing corner would get stretched across the whole screen and the shape would collapse. Adding `scroll` back onto the cover's `top` gives its position at scroll `0`, so the video peels away from where you last saw it, and the article slides up underneath.

`gl.uniform2f` and `gl.uniform1f` send values to the GPU. A **uniform** is the same for every point, unlike an attribute. Here the uniforms are the start box, the end box and the progress: everything the shader needs to place each point.

### 05 — Move every point, each a little late

The **vertex shader** is a small program, written in GLSL, that the GPU runs once for every point in the grid, all in parallel. Its job is to say where that point lands on screen.

The plain version blends each point from the start box to the end box. `mix(a, b, t)` is a linear blend: `a` when `t = 0`, `b` when `t = 1`, halfway at `0.5`.

```glsl title="05-straight.glsl"
vec2 xy = mix(u_fromXY, u_toXY, u_progress);
vec2 wh = mix(u_fromWH, u_toWH, u_progress);
```

Every point uses the same `u_progress`, so the whole rectangle moves as one: a flat shrink into the corner. Turn the delay off in the figure below to see exactly that.

The genie comes from giving each point its own **lag**: how late it starts.

```glsl title="05-genie.glsl"
float lag = (pow(1.0 - a_pos.x, 1.5) + pow(1.0 - a_pos.y, 1.5)) * 0.5;
float p = smoothstep(lag * 0.3, 0.7 + lag * 0.3, u_progress);

vec2 xy = mix(u_fromXY, u_toXY, p);
vec2 wh = mix(u_fromWH, u_toWH, p);
```

Reading it piece by piece:

- `1.0 - a_pos.x` is `0` on the right edge and `1` on the left. `1.0 - a_pos.y` is `0` on the bottom edge and `1` on the top. Averaging the two makes `lag` `0` at the bottom-right corner (nearest the dock) and `1` at the top-left.
- `pow(…, 1.5)` makes lag grow slowly near the leading corner and faster further away, so the bend is gentle where it starts.
- `smoothstep(start, end, v)` returns `0` before `start`, `1` after `end`, and an eased S-curve in between. Each point gets its own window: the leading corner moves while progress goes from `0` to `0.7`, and the far corner moves from `0.3` to `1.0`.
- `p` is that point's own progress. Using `p` instead of `u_progress` in `mix` is the whole trick.

<GenieVideoFigure step="bend" />

Drag the progress slider with the delay on. The dot (the leading corner) is already near the dock while the ring (the trailing corner) has barely left the cover, and the sheet stretches between them.

Adding the two axes rather than measuring a straight-line distance from the corner matters. A straight-line distance makes rings of equal lag around the corner, and the sheet creases along a diagonal. The sum changes smoothly along both edges, so they stay smooth curves.

Things to try in the real component:

- Change `0.3` to `0.5`: a bigger spread, a more dramatic stretch.
- Change `1.5` to `1.0`: the delay grows evenly and the curve gets stiffer.
- Swap `1.0 - a_pos.y` for `a_pos.y`: now the top-right corner leads, which suits a dock at the top-right.

### 06 — Turn pixels into WebGL coordinates

Everything so far is in CSS pixels, measured like the DOM: `(0, 0)` at the top-left with `y` growing downwards. WebGL doesn't use pixels. It uses **clip space**: the canvas always runs from `−1` to `1` on both axes, `(0, 0)` is the centre, and `y` grows upwards.

<GenieVideoFigure step="clip-space" />

```glsl title="06-clip-space.glsl"
float angle = sin(p * 3.14159) * -0.05; // 0 at both ends, a slight tilt mid-way
vec2 local = (a_pos - 0.5) * wh;
vec2 bent = mat2(cos(angle), sin(angle), -sin(angle), cos(angle)) * local;
vec2 screen = xy + wh * 0.5 + bent;

vec2 clip = screen / u_res * 2.0 - 1.0;
gl_Position = vec4(clip.x, -clip.y, 0.0, 1.0);
```

Line by line:

- `sin(p * 3.14159)` is `0` at `p = 0`, peaks at `p = 0.5`, and is back to `0` at `p = 1`. Multiplied by `-0.05` (radians, about 3°), it gives a slight tilt that only exists in flight, so the video sits straight at both ends.
- `local` is the point's offset from the plane's centre, in pixels. Measuring from the centre makes the rotation spin around the middle instead of a corner.
- `mat2(…) * local` is a **rotation matrix**. It turns the offset by `angle`.
- `screen` adds the box position, half the box size (back to the centre), and the rotated offset. This is the final position in CSS pixels.
- `screen / u_res` makes it `0..1` across the canvas, `* 2.0 - 1.0` makes it `−1..1`, and `-clip.y` flips the DOM's downward `y` to WebGL's upward one.

`gl_Position` is the shader's output: where this point goes. The two extra numbers, `0.0` depth and `1.0`, are what flat 2D drawing always uses.

### 07 — Crop like a cover image and round the corners

The **fragment shader** runs once for every pixel the triangles cover and decides its colour. This is where the video is sampled, cropped and given rounded corners.

**Cropping.** The video is 16:9, but the plane isn't always: it's wide as a cover, and squeezed or stretched mid-fold. Stretching the video to fit would squash it. Instead we do what `object-fit: cover` does: compare the plane's shape to the video's and only sample the middle part that fits.

```glsl title="07-cover-crop.glsl"
float aspect = v_size.x / v_size.y;
vec2 scale = vec2(min(aspect / u_texAspect, 1.0), min(u_texAspect / aspect, 1.0));
vec3 color = texture2D(u_tex, (v_uv - 0.5) * scale + 0.5).rgb;
```

If the plane is narrower than the video, `scale.x` drops below `1` and we read a narrower slice of the frame, centred because of the `- 0.5 … + 0.5`. If it's wider, `scale.y` shrinks instead. `texture2D` reads the video's colour at that spot.

**Rounded corners.** WebGL draws sharp-cornered triangles, so we make the corners transparent ourselves. The difficulty is that the sheet is stretched by different amounts in different places, so "16 pixels from the edge" can't be worked out from the box sizes. Instead we ask the GPU how fast things change on screen.

<GenieVideoFigure step="crop-corner" />

```glsl title="07-corners.glsl"
vec2 pxPerUv = 1.0 / vec2(
  length(vec2(dFdx(uv.x), dFdy(uv.x))),
  length(vec2(dFdx(uv.y), dFdy(uv.y)))
);
vec2 q = min(uv, 1.0 - uv) * pxPerUv; // pixels to the nearest edges
if (q.x < r && q.y < r) return r - length(vec2(r) - q);
return min(q.x, q.y);
```

- `dFdx(uv.x)` is how much the texture position changes from this pixel to the one on its right; `dFdy` does the same downwards. Turned into a length and inverted, that's "how many screen pixels per unit of texture" at this exact spot, however stretched it is.
- `min(uv, 1.0 - uv)` is how far this point is from the nearest left/right and top/bottom edge, in texture units. Multiplying by `pxPerUv` converts it to real pixels: `q`.
- Inside the corner square (both distances under `r`), the pixel survives only if it's within `r` of the corner circle's centre. Everywhere else, the distance to the nearest edge is enough.

The result is how far inside the rounded shape the pixel is. A pixel right on the edge gets about half opacity and anything outside is transparent, which also smooths the edge. `r` is 16 CSS pixels times the device pixel ratio, because the GPU counts real device pixels.

### 08 — Make the dock usable, respect motion settings, clean up

**The dock as a button.** Before the video lands, the dock would be an invisible button stealing clicks from the text underneath. So it starts with `pointer-events: none` and `tabIndex = -1`, which means mouse clicks pass through it and Tab skips it. Once progress reaches `1`, both switch on. Clicking it, or pressing Enter on it, smooth-scrolls back to the top, and because the fold follows scroll, the video unfolds into the cover.

<GenieVideoFigure step="dock" />

```ts title="08-dock.ts"
const nowDocked = progress >= 1;
if (nowDocked !== docked) {
  docked = nowDocked;
  dock.style.pointerEvents = docked ? "auto" : "none";
  dock.tabIndex = docked ? 0 : -1;
}
```

The `nowDocked !== docked` check means we only touch the DOM when the state actually changes, not 60 times a second.

**Reduced motion.** Some people set their system to reduce motion because animation makes them feel unwell. `matchMedia("(prefers-reduced-motion: reduce)")` reads that setting. When it's on, the video pauses on a single frame. The fold still follows the scroll, because that movement is something the reader is doing themselves.

**Fallback.** If `getContext("webgl")` returns nothing (very old devices, or WebGL turned off), the video element is simply placed inside the cover box and shown as a normal video.

**Cleanup.** When the component is removed, everything it started must stop.

```ts title="08-motion-and-cleanup.ts"
if (motion.matches && !video.paused) video.pause();

return () => {
  cancelAnimationFrame(raf);
  video.pause();
  video.removeAttribute("src");
  gl.deleteTexture(texture);
  gl.deleteProgram(program);
};
```

`cancelAnimationFrame` stops the loop, removing `src` lets the browser release the video download, and the `delete` calls free GPU memory. The cleanup leaves the WebGL context alive on purpose. In development, React mounts each component twice to catch bugs, and the second mount gets the same context back from the same canvas. A destroyed context can't be revived, so the second mount would draw nothing.

### Make your own variation

You now have every piece. Most new effects in this family come from changing only one of them:

- **Move the end box.** Pin the dock top-right, or make the end box a thumbnail in a list. Then point the lead corner at it (step 05).
- **Change the trigger.** Drive `progress` from a button and a timer instead of scroll, and the same shader becomes a minimise animation.
- **Reverse it.** Start from a small card and end at a large frame, and you get a "card opens into full screen" transition.
- **Swap the picture.** Anything you can draw to a canvas or video can be the texture: an image, a live camera, another canvas.

The general recipe is: mark the start and end with boxes, draw the content yourself on a mesh, map your input to `0..1`, and give each point its own timing.
