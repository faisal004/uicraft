The cover and the larger artwork below are the same visual object. Open the story, then go back: the browser carries that object between layouts while the surrounding text changes. That continuity gives the motion a job.

## Implementation

Copy this one component into a React app. It includes its own artwork and styles, so there are no image assets or animation packages to install. The button icons use `lucide-react`. The live demo above renders this exact source.

```tsx title="view-transition-demo.tsx"
"use client";

import { ArrowLeft, ArrowUpRight } from "lucide-react";

import { flushSync } from "react-dom";

    <div className="vt-art" role="img" aria-label="Illustrated desert mountains at sunset">

      <span className="vt-art-label">FIELD NOTES<br />THE WEST</span>
      <span className="vt-art-number">01</span>
    </div>
  );

  function toggle() {
    if (
      !document.startViewTransition ||
      window.matchMedia("(prefers-reduced-motion: reduce)").matches
    ) {
      setOpen((current) => !current);
```

Use this pattern for a thumbnail becoming a detail view, a card becoming a panel, or an item changing position in a collection. It is a **same-document** transition: the URL stays put and React changes the DOM. A browser without `startViewTransition` still gets the complete interaction, just without the animation.

## How it works

### 01 — Begin with two ordinary layouts

The visible structure is a cover, a title, a short description, and a button. React state chooses whether they appear as a compact cover or a larger story. Before adding animation, clicking the button should already show the right content.

```tsx title="01-layout.tsx"
const [open, setOpen] = useState(false);
const artwork = <div className="vt-art">FIELD NOTES</div>;

return (
  <>
    <button type="button" onClick={() => setOpen((value) => !value)}>
      {open ? "Back to cover" : "Open story"}
    </button>
    <div className={open ? "vt-detail" : "vt-cover"}>
      {artwork}
      <h3>Where the light stays longer</h3>
    </div>
  </>
);
```

The browser now has two useful views to compare. Without a transition, the artwork jumps from the small slot to the large one.

### 02 — Name the element that persists

`view-transition-name` gives the artwork an identity in both views. The browser takes a snapshot of the named element before and after the DOM update and matches those snapshots. Its position and size can then animate as one object. The name must be unique among elements visible in either view; giving two visible cards the same name makes the transition skip.

```css title="02-identity.css"
.vt-art {
  view-transition-name: uicraft-cover;
}
```

Try removing that declaration from the finished component. The content still changes, but the artwork loses its clear path between layouts.

### 03 — Put the DOM change inside a transition

`document.startViewTransition(update)` asks the browser to capture the old view, run `update`, capture the new view, and animate between them. `update` must actually change the DOM. The API returns a `ViewTransition` object with promises for advanced coordination; this small interaction does not need to wait on them.

```tsx title="03-browser-api.tsx"
document.startViewTransition(() => {
  // Change the DOM here.
});
```

React usually batches `setOpen`, so calling it alone inside `update` may let the callback finish before the new DOM is present. `flushSync` commits this one change before the browser takes its second snapshot.

```tsx title="03-react-update.tsx"
import { flushSync } from "react-dom";

document.startViewTransition(() => {
  flushSync(() => setOpen((current) => !current));
});
```

### 04 — Tune the motion and keep the action usable

The browser supplies a default transition. Target the named group's pseudo-element to set the artwork's travel time. The rest of the page can crossfade while the artwork keeps its identity.

```css title="04-duration.css"
::view-transition-group(uicraft-cover) {
  animation-duration: 450ms;
  animation-timing-function: ease-in-out;
}
```

Try `150ms`, then `900ms`. The first is hard to follow; the second makes the interface feel slow. Timing is useful when it helps someone understand where an object went.

The feature check and motion preference check both take the plain state-update path. The button remains a button, exposes its expanded state with `aria-expanded`, and has a visible keyboard focus outline. The browser cleans up its temporary snapshot elements when the transition ends; there are no listeners or timers to remove.

```tsx title="04-fallback.tsx"
if (
  !document.startViewTransition ||
  window.matchMedia("(prefers-reduced-motion: reduce)").matches
) {
  setOpen((current) => !current);
  return;
}
```

### 05 — A second use: switch the page theme

A theme switch does not have one object moving between slots. Instead, the entire page changes colors. This site's theme button uses the same API to crossfade from the old page snapshot to the new one. Try it here; the rest of the site changes while the fixed-color cover demo stays readable.

<ThemeToggle className="mt-4 inline-flex items-center gap-2 rounded-lg border border-foreground/25 px-4 py-2 text-sm text-foreground hover:bg-foreground/10" label="Switch site theme" />

The theme update changes the root `dark` class and `color-scheme` synchronously, so it needs no React `flushSync`. It also saves the choice to `localStorage`. The important transition path in this site's `ThemeToggle` component is:

```tsx title="theme-switch-core.tsx"
const nextDark = !document.documentElement.classList.contains("dark");

if (
  window.matchMedia("(prefers-reduced-motion: reduce)").matches ||
  !document.startViewTransition
) {
  applyTheme(nextDark);
  return;
}

document.startViewTransition(() => applyTheme(nextDark));
```

Here `root` means the full document snapshot, and CSS controls its fade. The cover example instead gives one element a distinct name so the browser can track its size and position. The site's global CSS uses a short 200ms fade for the theme:

```css title="theme-fade.css"
::view-transition-old(root) { animation: 200ms ease-out both theme-fade-out; }
::view-transition-new(root) { animation: 200ms ease-out both theme-fade-in; }

@keyframes theme-fade-out { to { opacity: 0; } }
@keyframes theme-fade-in { from { opacity: 0; } }
```

### 06 — Choose the right transition

- **One object changes size or position:** give it a unique `view-transition-name`, as with the cover.
- **The whole page changes appearance:** transition the root view, as with the theme switcher.
- **The URL changes in Next.js:** use React's `<ViewTransition>` with `Link` navigation; the [Next.js guide](https://nextjs.org/docs/app/guides/view-transitions) covers shared elements across routes.

The [MDN View Transitions guide](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API/Using) explains the snapshots and pseudo-elements in more depth.
